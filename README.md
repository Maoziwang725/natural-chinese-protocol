# 自然中文协议 Natural Chinese Protocol

一份用于识别并消除中文文本中 AI 生成痕迹的写作规范。适用于任何大语言模型。

## 这是什么

大模型写出来的中文有一套相当稳定的坏习惯：喜欢强行升华，喜欢三段式排比，喜欢在每个判断后面找补一句，喜欢把"是"写成"扮演着……的关键角色"。这些毛病单看每一条都不算错，但堆在一起，读起来就是不像人写的。

这份协议把这些模式逐条拆开，给出诊断方法和改写示例，可以直接作为 AI 写作的约束条件使用，也可以当成人工审校的检查清单。

内容分三部分：

- **内容特征模式**：宏大叙事、剥洋葱式解释、强行升华结尾
- **语言与语法模式**：排比滥用、谓语复杂化、教科书式确信感、语篇标记泛滥、翻译腔、代词"它"的滥用、破折号泛滥
- **格式与排版模式**：段落对称性、表情符号泛滥

每条都配了修改前 / 修改后的对照文本，以及改动理由。

## 怎么用

协议正文（`SKILL.md`）是纯 Markdown，不依赖任何平台的特定功能，几种用法都行。

**作为 Claude Code skill 安装。** 如果你用 Claude Code，一条命令 clone 到自己的 skills 目录就行，之后 Claude 会按 `SKILL.md` 头部里写的触发条件自动调用，不用每次手动粘贴：

```bash
git clone https://github.com/Maoziwang725/natural-chinese-protocol ~/.claude/skills/natural-chinese-protocol
```

装好后重启 Claude Code，让它识别到这个新 skill。想要它对某个项目生效，把上面的 `~/.claude/skills` 换成该项目下的 `.claude/skills` 即可。

**直接当 prompt 用。** 复制 `SKILL.md` 全文，粘贴到任意模型的对话框，后面接上要改的文本。最省事，也最通用。

**写进长期指令。** 多数 AI 工具都提供某种形式的持久化配置，比如系统提示词、自定义指令、项目级配置文件。把协议正文放进去，之后不用每次重复粘贴。具体位置查各自的文档。

**当人工审校清单用。** 协议本身是给人看的，自己写完中文之后按三部分逐条过一遍也有效，尤其是"教科书式确信感"和"强行升华结尾"这两条，人写东西时也容易犯。

## 它不做什么

写清楚边界，比写清楚功能更重要。

**只管语言层面。** 这份协议处理的是"这段话像不像人写的"，不处理"这段话说得对不对"。事实错误、逻辑漏洞、专业内容是否成立，都不在它的职责范围内。改完之后该核对的还得核对。

**不做跨文体改写。** 公文不会被改成聊天体，聊天记录也不会被改成公文。协议要求先界定场景再动手，就是为了防止这种事。

**不追求"越短越好"。** 这一条是刻意写进去的。市面上多数去 AI 味的方案会滑向另一个极端，把句子切成一顿一顿的短句，读起来像电报。那同样不像人说话，只是换了一种不像。协议里专门有一节要求保留正常的句子延展度和合理的连词。

**词表会过时。** 黑名单里的词是当下这一批模型的高频习惯。模型会更新，流行语也会变，这份清单需要跟着维护，不是一劳永逸的东西。

## 一些设计取舍

**用例子说话，不用规则说话。** 抽象规则容易被理解成另一种套路。每条模式都给了具体的修改前后文本，让人和模型都能直接对照。

**保留认知边界。** 协议要求用"预计""在很大程度上""初步看来"替代"无疑""绝对"。这不只是措辞问题，真实的人在写东西的时候本来就有不确定的地方，把这些痕迹抹平，文本反而失真。

**盯住重复的句式，不只是重复的词。** 破折号那一条是后来补的。触发它的场景是一份并列清单，每个条目都用同一个破折号句式展开，单看每条都挑不出毛病，连起来读就露馅了。词表能拦住高频词，拦不住高频结构，所以这类模式需要单独列出来。
