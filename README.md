# 自然中文协议 Natural Chinese Protocol

大模型写中文有一套稳定的毛病。喜欢三段式排比，喜欢在每句判断后面找补一句，喜欢把"是"写成"扮演着……的关键角色"，结尾永远"挑战与机遇并存"。这些毛病单看每一条都不算错，堆在一起，读着就不像人写的。

举个例子。让模型写一段产品介绍，它大概率会给你这样的东西：

> 新一代智能手表的发布，标志着我们在可穿戴设备领域的深度赋能。它不仅提升了续航能力，优化了监测精度，更重塑了用户的健康管理闭环。值得注意的是，这无疑是一款绝对能引领潮流的产品。未来依然可期。

三段排比、一个"无疑"、一个"绝对"、一个"值得注意的是"、一个"未来可期"结尾。五个毛病挤在四句话里。

这份协议做的事情就是把这些模式逐条拆开，告诉你怎么认、怎么改。可以直接塞给模型当约束条件，也可以自己写完中文以后拿来当检查清单对一遍。

## 用法

协议正文是 `SKILL.md`，纯 Markdown，跟平台无关。

**塞给 Claude Code 当 skill。** 一条命令，装完重启就能用，Claude 会在你写中文的时候自动按协议来：

```bash
git clone https://github.com/Maoziwang725/natural-chinese-protocol ~/.claude/skills/natural-chinese-protocol
```

要让它只对某个项目生效，把 `~/.claude/skills` 换成那个项目下面的 `.claude/skills`。

**直接当 prompt 用。** 复制 `SKILL.md` 全文，粘到任意模型的对话框里，后面接上要改的文本。

**写进长期指令。** 多数 AI 工具有某种持久化配置（系统提示词、自定义指令、项目级配置文件），把协议正文放进去，以后不用每次粘。

**自己写完中文以后对着查。** 协议本身是给人看的，尤其"教科书式确信感"和"强行升华结尾"这两条，人写东西的时候也容易犯。

## 协议管什么、不管什么

只管语言层面——"这段话像不像人写的"。事实对不对、逻辑通不通、专业内容是否成立，不在它的管辖范围。改完了该核对的还得核对。

不做跨文体改写。公文不会被改成聊天体，聊天记录也不会被改成公文。协议第一步就是先判断场景，定好语域再动手。

不追求"越短越好"。市面上不少去 AI 味的方案会滑向另一个极端——把句子切成一顿一顿的短句，读起来像电报。那同样不像人说话，只是换了一种不像。协议里专门留了一条，要求保持句子正常的延展度和合理的连词。

词表会过时。黑名单里的词是当下这一批模型的高频习惯，模型会更新，流行语也会变。这份清单不是一劳永逸的，需要跟着维护。发现某条规则执行过头或者没触发，欢迎提 issue。
